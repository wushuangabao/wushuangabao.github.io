# 六元围棋 · Six Side Go

原 Cocos Creator 六元围棋的纯网页重构。HTML、CSS、原生 JavaScript 与 SVG，无运行时框架、无 CDN 依赖。开发时无需构建，适用于 GitHub Pages 等静态托管，也可以直接打开 `index.html`。

## 本地运行

需要 Node.js 18 或以上；无需安装 npm 依赖。

```sh
npm start
```

打开 http://127.0.0.1:4173。服务仅监听本机。部署时保留 `index.html`、`style.css`、`favicon.ico`、`src/game.js`、`src/ai.js`、`src/app.js`、`src/board-view.js` 和 `assets/audio/`，路径均为相对路径。

## 发布构建

运行 `npm run build` 会清理并生成 `dist/`，将四个脚本按依赖顺序合并为 `assets/game.js`，输出独立的静态游戏。可进入 `dist/` 后运行 `npx --yes serve .` 验证；发布时上传该目录的全部内容。`dist/` 和本地检查日志不提交到 Git。

Pogglo 游戏名为“六元围棋”，永久标识为 `six-side-go`，发布配置保存在 `pogglo.json`，后续发布沿用同一标识更新游戏。游戏地址：https://pogglo.com/wha/six-side-go/ 。开局与弹窗关闭直接使用按钮事件，兼容限制表单提交的托管环境。

## 玩法与操作

- 开局可选“与 AI 对弈”或“同屏双人”，蓝方先行。AI 模式可选自己执蓝先手或执红后手。快棋每手 15 秒、常规 60 秒、慢棋 300 秒，也可自定义 0.1–180 分钟（最多一位小数）。超过一分钟的计时以“分:秒”显示。进度条按实际剩余毫秒逐帧匀速衰减；换手重新计时，切换标签页仍计时。
- AI 为本地入门陪练，无需网络、账号或 API 密钥。与玩家共用落子合法性规则，评估提子、救子、独立眼区及新增势力覆盖，优先补眼做活、连接断开的围墙，并在安全时疏展争空；填自家空和重复覆盖不会获得同等收益。AI 思考期间禁止代 AI 落子、停手和认输，可以暂停、悔棋或新开一局。
- 眼形评估以真实连接为准：同一个连通空区只算一眼，须由同一棋块包围且每个空点直接接触该棋块；分隔空区可做出第二眼，尚未封闭的眼形只给准备分。势力沿空点衰减、不能穿过敌子，重叠覆盖不重复计分，远离己方的孤立落子扣分。对全部合法落子粗估后，检查前六个候选及最多两个紧急提/救子点，每点最多八个对方应答；遇到打吃再检查最多四个延长或反提点。仍是有限候选的启发式搜索，未训练神经网络，不保证复杂死活、征子或劫争的最优解。
- AI 模式悔棋撤回玩家上一手及 AI 应手；AI 尚未应手时仅撤玩家一步，玩家执红时保留 AI 的开局。暂停、形势判断、终局与换局会取消旧的 AI 任务，恢复或争议续弈后按当前执子方继续。
- 玩家停手后，AI 先按收官时的自动死子预标与面积计分试算；若 AI 严格领先，立即停手进入确认，即使仍可提子或救子也优先收官。持平或落后时沿用选招逻辑：没有紧急提/救子要点或没有值得下的落点时也会停手。试算不改动对局，只采用程序能证明的死子；人工调整标记仍可能改变胜负。连续停手后由玩家标记、核对死子，点击“确认死子并结算”即代双方确认；也可指定任意一方先行继续对弈。
- 原棋盘的 360 个落点、540 条无向连接保持一致，每点连接三个邻点，包含边界的特殊连接。
- 六个顶角不设落点；角旁的两点直接相连。外框沿 48 个边界落点闭合，六处角连接绘成轻微圆弧，与两侧平滑衔接，不改变落点或连接关系。
- 同色相连为一块，相邻空点为气。先提掉无气的对方棋块，自身仍无气则禁止落子。单劫禁止立即回提。合法落子后，若棋盘和下一手行棋方与当前分支的历史局面完全一致，按循环和棋结束；单纯停手不触发和棋，悔掉的未来局面不参与判重。
- 双方连续停一手后进入死子确认并停止计时。程序先预标能够证明死亡的棋子；玩家可点选任意棋子，标记或取消整块死子。每次修改标记都撤销双方已有确认；双方分别确认后，实际移除死子并结算。确认前只预览，原棋盘和提子数不变。
- 死活有争议时，点击“有争议，继续对弈”，由认为存在死子的一方选择先行。清除全部标记及确认，保留原棋盘和对局历史，停手计数清零，本手时间重新开始。再次连续停手会重新预判并进入确认。
- 对局中可打开“形势判断”：保持当前计时状态，复用自动死子预标和整块人工标记，即时对比双方活子、围空、潜力空地及参考总分。棋盘以蓝红实心方块标围空、空心方块标潜力、灰点标双方争夺，远端势力不足的空地保留为尚不明朗。活子按未标死棋子暂计，另列两眼判活数量。关闭后清除临时标记，原棋盘、行棋方、提子、停手及历史保持不变，判断期间正常扣时、超时判负，退出不重置时间；若进入前已手动暂停，判断期间及退出后仍保持暂停。
- 计分仍采用棋子数加仅接触己方的连通空地；混合边界空地中立，无贴目。清除死子会更新提子统计，但提子不额外加分。
- 悔棋撤销上一手落子或停手，恢复提子、劫、回合及该手开始操作前的剩余时间。终局后锁定棋盘及悔棋。
- “暂停计时”冻结剩余时间及进度条，并暂时禁止落子、停手、悔棋和认输；点击“继续计时”后从原剩余时间恢复。后台运行仍计时，请离开前主动暂停。
- 支持鼠标、触屏，以及方向键选点、回车／空格落子。手机先点按棋盘，以点按位置为中心放大；再次点按才尝试落子，无论成功或位置不可落子，都会自动还原完整棋盘。无效位置不落子、不换手，并提示原因。放大后长按至少 300 毫秒再拖动可移动视野，拖动和长按松手不会落子，不显示棋盘滚动条。
- 认输或超时后保留原棋盘，自动进入终局复盘并预标死子。可继续整块标记或取消死子，查看双方分数，直到新开一局；复盘估分不改变已确定的胜负，也不实际提走棋子。
- 提供音效开关、规则说明、新局及认输确认。对局只保存在当前页面内存，刷新会重置。

## 结构

- `src/game.js`：独立规则模型，棋盘拓扑、提子、单劫、计分、计时与状态快照。
- `src/ai.js`：本地落子评估、可取消的 AI 回合调度和整轮悔棋。
- `src/app.js`：SVG 渲染、交互、音效与对局 UI。
- `src/board-view.js`：棋盘视野和点按／长按拖动状态。
- `style.css`：桌面双栏、窄屏上下布局、矮屏紧凑布局。
- `tests/game.test.cjs`：核心规则回归测试。
- `tests/ai.test.cjs`：AI 提子、救子、分眼做活、连接保眼、疏展占地、合法落子、整轮悔棋、取消旧任务、超时、收官与固定种子自弈；眼形另用规则模型的活棋证明核对，占地另用形势模型核对。
- `tests/scoring.test.cjs`：自动死子预判、人工确认、争议续弈及循环和棋回归测试。
- `tests/position.test.cjs`：中盘势力估算、棋墙阻挡、开局与双活、颜色和几何对称、手动标记重算及终局计分隔离。
- `scripts/verify-source.cjs`：只读核对原工程的全部邻点及 100 个固定种子局面的计分。

## 验证

自动预判使用保守的活棋证明及局部攻防搜索：反复筛选有两个独立有效眼区的棋块，仅研究被这些活棋封闭的区域；即使被围一方先行并选择最佳应对，仍会全部被提时才预标。每片区域最多 12 个落点，全盘最多搜索 12000 个节点，深度为区域点数的两倍加四。劫争、双活、开放棋形、超出搜索范围或不能证明的棋块不预标，不能把“没有标记”等同于“已经判活”。最终以双方确认的标记为准。

形势判断参考[野狐公开的形势展示功能](https://www.foxwq.com/news/listid/id/9148.html?lang=zh)及 [GNU Go 的势力文档](https://www.gnu.org/s/gnugo/gnugo_13.html)，为六边形棋盘独立实现本地启发式估算，没有接入野狐或神经网络引擎。先移除标记死子，再沿真实三邻点拓扑分别扩散双方势力；棋子阻挡敌方势力，气紧棋块减弱，传播按距离衰减。单色边界、面积不超过边界棋子两倍且每点距边界不超过三步的紧凑空区归为当前围空，其余按势力分成蓝方潜力、红方潜力、双方争夺和不明朗。双方直接接触的共享气不分配归属。最多迭代 96 轮，变化小于 0.000001 时提前结束；主导势力不足 0.08 的点保留，双方相对差小于 0.28 的点视为争夺。

参考总分为未标死棋子数 + 当前围空数 + 潜力空地数；它是势力倾向的对比，不是落子搜索后的终局预测或胜率。攻杀、劫争、侵入、先后手均可能改变归属，不能保证最优对弈下的结果。估算只在进入判断或修改标记等界面更新时执行，不在计时动画中执行。`score()` 和双方确认后的实际面积计分保持独立，潜力不会写入终局结果。
